# Накладные расходы коллектора (P1.2 / NFR 4.1)

## Методика

`npm run bench:collector` (`e2e/perf.mjs`) запускает Chrome дважды в чистых
профилях: без расширения и с загруженным `dist/`. В каждом профиле пять раз
открывается одна и та же fixture-страница (`e2e/fixture.html`) с
`Performance.enable` и снимаются кумулятивные счётчики CDP через 2,5 с после
`load`:

- `TaskDuration` — суммарное время задач основного потока;
- `ScriptDuration` — время исполнения JS;
- `LayoutCount` — число layout-проходов;
- `LongTask` — число long tasks (`PerformanceObserver` с `buffered: true`);
- `JSHeapUsedSize` — размер JS-heap;
- `loadEventEnd` — время события `load`.

Сравниваются медианы пяти прогонов. Бюджет: рост `TaskDuration` не более 5 %
от baseline **или** не более 25 мс (абсолютный порог нужен, потому что
localhost-загрузка занимает десятки миллисекунд и процент шумит), рост
JS-heap не более 1,5 МБ.

## Зафиксированный результат

Прогон на Windows, Chrome for Testing, headless, 5 итераций:

| Показатель | Без расширения | С расширением | Разница |
| --- | ---: | ---: | ---: |
| TaskDuration | 165,1 мс | 179,1 мс | +14,1 мс |
| ScriptDuration | 140,9 мс | 150,0 мс | +9,1 мс |
| LayoutCount | 2 | 2 | 0 |
| LongTask | 1 | 1 | 0 |
| JSHeapUsedSize | 1,20 МБ | 1,51 МБ | +0,31 МБ |
| loadEventEnd | 56,8 мс | 31,9 мс | −24,9 мс |

Overhead `TaskDuration`: **+8,5 %** при абсолютной разнице 14,1 мс; heap:
+0,31 МБ. Оба показателя в бюджете (абсолютный порог 25 мс). Между прогонами
процент колеблется примерно в диапазоне 5–9 % при абсолютной разнице
8–14 мс, поэтому бюджет опирается на абсолютный порог, а не только на процент.
Количество long tasks не меняется (`1 → 1`), лишних layout-проходов нет.

## Решение

Разделение page script на «лёгкий ранний» и «тяжёлый по требованию» не
требуется: абсолютная разница в несколько миллисекунд и укладывается в
бюджет. Ограничение зафиксировано осознанно:

- коллектор регистрируется на всех `http/https` страницах с
  `document_start`, чтобы не потерять LCP/FCP/TTFB, если панель откроют
  позже;
- тяжёлые observers (LongTask, LayoutShift, Interaction) используют
  `buffered: true`, поэтому старт аудита не требует перезагрузки страницы;
- при существенном изменении page script замер нужно повторить и обновить
  этот документ. Если overhead выйдет за бюджет, план — вынести
  LongTask/INP observers за событие `SESSION_START`.
