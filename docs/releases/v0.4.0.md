# Web Performance Auditor v0.4.0

Минорный релиз расширения для локального аудита Core Web Vitals: LCP, CLS, INP,
FCP и TTFB с атрибуцией к DOM и диагностикой причин. Закрыты четыре ограничения
v0.3.0: автоматический Firefox smoke, Firefox-zip в релизе, расширенные миграции
схемы и p75-агрегация по сессиям.

## Установка

### Chrome / Chromium

1. Скачайте `web-performance-auditor-0.4.0.zip` из ассетов релиза.
2. Распакуйте архив в постоянную папку.
3. Откройте `chrome://extensions`, включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение» и выберите папку.
5. Откройте обычную http/https страницу и нажмите иконку расширения — Side
   Panel откроется справа.

Требования: Chrome/Chromium 116+. Проверьте SHA-256 по файлу
`web-performance-auditor-0.4.0.zip.sha256`.

### Firefox

1. Скачайте `web-performance-auditor-firefox-0.4.0.zip` из ассетов релиза.
2. Откройте `about:debugging#/runtime/this-firefox`.
3. Нажмите «Загрузить временное дополнение» и выберите скачанный zip.

Firefox устанавливает неподписанные расширения только как временные. Для
постоянной установки пакет нужно подписать в Mozilla Add-ons; идентификатор
`web-performance-auditor@wwsxdc.github.io` уже задан в манифесте. Требования:
Firefox 142+. Проверьте SHA-256 по файлу
`web-performance-auditor-firefox-0.4.0.zip.sha256`. Подробности —
[`docs/firefox.md`](../firefox.md).

## Что добавлено

- **Автоматический Firefox smoke.** `e2e/firefox.mjs` (Selenium + geckodriver)
  устанавливает `dist-firefox/` как временное дополнение, открывает панель через
  `moz-extension://<uuid>/` из привилегированного Marionette chrome-контекста и
  проверяет 16 сценариев: старт аудита, пять метрик, атрибуцию LCP, оверлей,
  эксперимент с блокировкой `blocked.test`, очистку DNR, экспорт JSON/Markdown,
  p75 и остановку сессии. CI job `firefox` запускает его в headless-режиме.
- **Firefox-zip в релизе.** `npm run package` собирает
  `web-performance-auditor-0.4.0.zip` и
  `web-performance-auditor-firefox-0.4.0.zip`, оба воспроизводимы и
  сопровождаются `.sha256`. `npm run verify:release` загружает Chrome-zip в
  Chrome и структурно проверяет Firefox-zip.
- **p75 по истории.** `GET_P75_AGGREGATE` считает nearest-rank p75 по
  LCP/INP/CLS/FCP/TTFB из завершённых, прерванных и импортированных сессий:
  одна последняя измеренная точка на сессию, активные/`unsupported`/`error`
  сессии исключаются. На вкладке «Данные» появился раздел «p75 по истории» со
  значением, рейтингом по порогам и числом сессий в выборке.
- **Расширенные миграции схемы.** `inspectStoredSession` /
  `inspectStoredExperiment` классифицируют запись как `current`, `migrated`,
  `future`, `unsupported` или `invalid`. Retention сохраняет записи будущих и
  неизвестных версий (их может прочитать более новая сборка) и удаляет только
  структурно повреждённые. Сессии, на которые ссылается running-эксперимент из
  будущей схемы, тоже сохраняются, чтобы после возврата новой версии он не
  остался без baseline/result.

## Что внутри

- Сбор пяти Core Web Vitals и атрибуция к элементам страницы.
- График сессии, события, детали метрик, копирование диагностики.
- SPA- и документные сегменты навигации.
- Эксперименты с временной блокировкой доменов (DNR) и сравнением метрик.
- Экспорт JSON и Markdown без query-параметров URL; импорт JSON и история
  сессий; p75 по истории.
- Статус полноты данных с причинами.
- Подсветка целей LCP/CLS/INP и обнаружение удаления/замены/перемещения.
- Локальное хранение, без сетевых отправок.

## Проверки релиза

- `npm run verify`: типы, lint, 218 unit-тестов, production-сборка.
- Chrome E2E: 48/48 PASS на финальном `dist/`, включая `P75_AGGREGATE`.
- Accessibility: axe-core 23 состояния + keyboard-путь по всем четырём
  вкладкам, 23/23, 0 serious/critical.
- Firefox smoke: 16/16 PASS на `dist-firefox/` в Firefox 159.0.1 (локально,
  headless); в CI используется `setup-firefox` с `firefox-version: latest`.
- Performance: `TaskDuration` +4,3–5,0 % (+7,6–8,5 мс), JS-heap в пределах
  ±0,32 МБ — в бюджете (абсолютный порог 25 мс, heap 1,5 МБ).
- `npm audit --omit=dev`: 0 уязвимостей.
- `npm run verify:release`: Chrome-zip загружается и рендерит side panel;
  Firefox-zip проходит структурную проверку.
- `web-ext lint --source-dir dist-firefox`: 0 ошибок (2 предупреждения
  `innerHTML` во внутренностях React-бандла).
- Оба zip воспроизводимы из чистого checkout; SHA-256 не зависит от часового
  пояса сборки.

## Известные ограничения

- Firefox-пакет неподписан: постоянная установка требует подписи Mozilla
  Add-ons.
- p75 считается по локальной истории (не более 50 сессий) и не заменяет
  field-данные CrUX.
- Миграции поддерживают известные старые версии (сейчас v1 → v2). Записи с
  неизвестной или будущей `schemaVersion` не читаются, но сохраняются; сессии
  защищаются от retention только для running-экспериментов, завершённые
  эксперименты из будущей схемы историю не удерживают.
- Импорт остаётся аддитивным: существующие записи никогда не перезаписываются,
  импортированная сессия доступна только для чтения.
- Поведение `declarativeNetRequest` и кэша в Firefox может отличаться от
  Chrome, поэтому сравнение эксперимента остаётся измерением, а не гарантией.
