# Security / privacy review (P2.3)

Дата: 2026-11-04  
Область: `v0.1.0`, Chrome MV3, сборка `dist/` из `main`.

## 1. Разрешения

| Разрешение | Зачем нужно | Минимальность |
| --- | --- | --- |
| `sidePanel` | Основной интерфейс | Обязательно |
| `storage` | Настройки, указатели сессии/эксперимента | Обязательно |
| `activeTab` | Старт аудита по действию пользователя | Обязательно |
| `scripting` | Динамическая регистрация page collector и инъекция bridge | Обязательно |
| `tabs` | URL/идентификатор активной вкладки, сообщения вкладке | Обязательно |
| `webNavigation` | Документные и SPA-сегменты | Обязательно |
| `declarativeNetRequest` | Блокировка доменов в эксперименте | Обязательно |
| `host_permissions: http://*/*, https://*/*` | Ранний сбор LCP/FCP/TTFB на любой аудируемой странице | Осознанно широкое; ограничено http/https |

`<all_urls>` и доступ к `chrome://`, `file://`, Chrome Web Store не
запрашиваются. `isAuditableUrl` дополнительно запрещает системные протоколы,
Chrome Web Store и не-http(s) схемы.

## 2. Сетевые отправки

- В `src/` отсутствуют `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`.
- Нет серверной части, аналитики, телеметрии и внешних шрифтов/скриптов.
- Все ресурсы попадают в `dist/` при сборке; `web_accessible_resources` не
  объявлены.
- `npm audit --omit=dev` (2026-11-04): `0` уязвимостей всех уровней.

## 3. Выполнение кода

- Нет `eval`, `new Function`, `document.write`, `innerHTML`/`outerHTML`.
- React экранирует текстовые данные; отчёт Markdown/JSON формируется из
  типизированных значений.
- Page script — собственный bundled-код, не принимает и не исполняет код
  страницы.
- CSP: MV3 default (`script-src 'self'`), отдельный `content_security_policy`
  не требуется.

## 4. Границы сообщений и лимиты

- Page → content: проверяются `event.source === window`,
  `event.origin === location.origin`, префикс `WPA_`, схема сообщения и размер
  (`PAGE_MESSAGE_LIMITS`: 64 КБ, 512 символов на строку).
- Content → background: `isExtensionMessage` валидирует тип и обязательные
  поля; background проверяет `sender.id`, активную вкладку и активную сессию.
- Хранение ограничено: 50 сессий, 500 событий и 1000 метрик на сессию, журнал
  диагностики — 30 записей по 500 символов.
- Навигация: метрики старого документа отбрасываются по `documentToken`;
  поздние сообщения после stop/reset не принимаются.

## 5. URL и приватность

- `sanitizeUrl` сохраняет только `origin + pathname`; query и hash (могут
  содержать токены) удаляются.
- E2E проверяет, что `token=secret` не попадает в JSON/Markdown.
- Диагностический журнал хранит scope и текст ошибки, без DOM и URL страницы.
- Данные не покидают профиль браузера; пользователь может удалить всё через
  «Данные» → «Очистить историю».

## 6. DNR-эксперименты

- Используются только `updateSessionRules` (не persistent rules).
- Правила имеют фиксированный диапазон id от `10000`, условие
  `requestDomains` + `tabIds`, действие `block`.
- Удаление проверяется чтением `getSessionRules`; при неудаче эксперимент
  помечается `failed`, указатель сохраняется и очистка повторяется при
  следующем старте service worker и при очистке истории.
- Отмена и завершение всегда очищают правила; E2E проверяет `rules=0`.

## 7. Зависимости и сборка

- Production-зависимости: `react`, `react-dom`, `recharts`, `web-vitals`,
  `idb` — без known critical/high.
- `axe-core`, `jsdom`, `fflate`, `puppeteer-core` — только dev.
- `npm run package` собирает zip из `dist/`, фиксирует mtime и пишет SHA-256;
  повторная сборка даёт тот же checksum (проверено локально).
- CI собирает и проверяет установку артефакта (`npm run verify:release`).

## 8. Остаточные риски

- Широкие `host_permissions` увеличивают поверхность: page collector
  запускается на всех http/https страницах. Это принято для раннего захвата
  метрик; overhead измерен и ограничен
  ([`docs/performance/collector-overhead.md`](../performance/collector-overhead.md)).
- Скомпрометированный профиль браузера или другая extension с большими
  правами может читать локальные данные.
- Нет автоматического обновления: пользователь сам отвечает за установку
  свежего артефакта.
