## 2. Что сделано

### 2.1. Основная функциональность и исправления P1

- Усилена граница page → content script: проверяются `event.source`,
  `event.origin`, размер сообщения (UTF-8), длина строк, рейтинги, статусы и
  источник метрики.
- Добавлены лимиты хранения: `maxSessions`, `maxEventsPerSession`,
  `maxMetricsPerSession`.
- Исправлена семантика навигации:
  - полная загрузка документа создаёт новый document-сегмент;
  - SPA-переходы создают отдельные SPA-сегменты и событие `spa-navigation`;
  - load-метрики (LCP/FCP/TTFB) остаются привязанными к документному сегменту;
  - CLS/INP привязываются к активному сегменту.
- Повторные callback-и одной метрики больше не считаются независимыми
  измерениями: в live-сессии сохраняются обновления, в экспорте — одна
  консолидированная запись на `metricId` и навигационный сегмент.
- Добавлены проверки полномочий эксперимента и очистка DNR-правил.
- Chrome API в side panel централизованы в `src/sidepanel/api.ts`.
- MutationObserver оверлея ограничен цепочкой родителей целевого элемента.
- Добавлены диагностические события `metric-update` и корректная атрибуция
  обновлений метрик.

### 2.2. Исправления по результатам code review

- Восстановление сессии после перезапуска service worker не прерывается при
  временном несовпадении URL: добавлены `pendingNavigationUrl`,
  `pendingNavigationSince`, grace-таймер и защита от «зависшей» навигации.
- Ограничена область fallback-метрик CLS/INP текущим document lineage; активный
  SPA-сегмент больше не получает чужое fallback-значение.
- Исправлена привязка `metric-update` для LCP/FCP/TTFB к документному сегменту.
- Размер page-сообщений считается в байтах через `TextEncoder`, а не по длине
  строки.
- `onTabUpdated` игнорирует события других вкладок.

### 2.3. Доработка по must-требованиям ТЗ

- **FR-04, buffered-события:**
  - при ошибке `observe({ buffered: true })` наблюдатель повторно запускается
    без `buffered`, чтобы сбор начался с момента подключения;
  - ограничение фиксируется диагностическим событием `collector-limitation`;
  - событие отображается в панели событий, карточке деталей и попадает в
    `limitations` JSON/Markdown-отчёта;
  - ограничение сохраняется между остановкой и повторным стартом сессии.
- **NFR 4.6, версии схемы:**
  - чтение сессий и экспериментов проверяет `schemaVersion`;
  - несовместимые записи не отдаются в UI;
  - при очистке такие записи удаляются, включая «зависшие» active-сессии;
  - добавлены unit-тесты.
- **NFR 4.4, доступность:**
  - мелкий текст `text-gray-400` заменён на `text-gray-500` во всех
    sidepanel/popup-компонентах;
  - цвета оверлеев затемнены для контраста белой подписи;
  - сохранены focus-visible, reduced-motion и семантические роли.
- **FR-16, popup:**
  - popup показывает URL, статус, время начала сессии и метрики;
  - fallback popup регистрируется, если Side Panel API недоступен.

### 4.2. Известные ограничения и неполное покрытие ТЗ

Это не блокеры текущего Chrome-релиза, но полного соответствия всем
must/should/could-пунктам ТЗ пока нет.

- **4.1 Производительность:** запись диагностических событий выполняется
  по одному, без пакетной обработки; page collector регистрируется для всех
  `http/https` страниц на `document_start`, а не только при активном аудите.
  Это сделано для захвата ранних метрик, но накладные расходы не измерены.
- **FR-14:** удаление и замена целевого элемента обрабатываются через
  `isConnected`; явное обнаружение «элемент перемещён» не реализовано.
  Перемещённый, но всё ещё подключённый элемент продолжает подсвечиваться.
- **NFR 4.6:** миграции старых схем нет. Несовместимые записи фильтруются при
  чтении и удаляются при очистке.
- **FR-04:** ограничение фиксируется, когда `buffered: true` выбрасывает
  ошибку. Если браузер молча принимает `buffered`, но не возвращает
  исторические записи, это надёжно определить нельзя. Восстановление всех
  событий до инъекции не гарантируется — это допускает само ТЗ.
- **4.4 Доступность:** контраст и focus-visible исправлены вручную; отдельного
  автоматизированного accessibility-аудита (пункт Could) нет.
- **4.5 Совместимость:** отдельный Firefox-адаптер и манифест (Should) не
  реализованы; целевая платформа релиза — Chrome.
- **Импорт JSON (Could)** ранее экспортированного отчёта не реализован.
- **Нагрузочный тест накладных расходов < 5% (Should)** не проводился.
