# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
| --- | --- |
| `0.1.x` | Да |

Расширение распространяется как распакованная сборка / zip-артефакт GitHub
Release. Автоматического обновления и серверной части нет.

## Как сообщить об уязвимости

Используйте приватный GitHub Security Advisory:
`https://github.com/wwsxdc/web-performance-auditor/security/advisories/new`.

Не открывайте публичный issue до подтверждения исправления. Укажите версию,
шаги воспроизведения и ожидаемое воздействие. Ответ — в течение 7 дней.

## Модель безопасности (кратко)

- Все данные (сессии, метрики, события, эксперименты) хранятся локально в
  `chrome.storage.local` и IndexedDB. Сетевых отправок нет: в `src/` нет
  `fetch`, `XMLHttpRequest` или `WebSocket`.
- Расширение не выполняет код страницы и не использует `eval`,
  `new Function`, `innerHTML` или удалённые скрипты.
- Page script работает в MAIN world и общается с content script только через
  `window.postMessage`; content script проверяет `event.source`, `event.origin`,
  префикс сообщения, размер (64 КБ / 512 символов на строку) и схему.
- Background проверяет отправителя (`sender.id`) и полномочия операций
  (активная вкладка/сессия).
- DNR-правила эксперимента создаются только как session rules, ограничены
  `tabIds` и `requestDomains`, удаляются при завершении, отмене, очистке
  истории и восстановлении service worker.
- Query-параметры и hash удаляются из сохраняемых URL (`sanitizeUrl`).

Подробный разбор — [`docs/security/privacy-review.md`](docs/security/privacy-review.md).

## Вне области

- Скомпрометированный профиль Chrome или другая расширение с более широкими
  разрешениями.
- Уязвимости браузера и сторонних зависимостей вне зафиксированных версий.
- DoS через страницу, на которой пользователь сам запустил аудит.
